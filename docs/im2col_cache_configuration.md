# im2col 输入缓存配置

## 硬件结构

`IM2COL_CACHE_BYTES` 指定卷积和 DW 共用的原始输入数据缓存容量。默认数据容量为 4096 字节，两路组相联，每条缓存行为 128 字节。数据缓存与共享 IA/PS RAM 分别统计。

```make
IM2COL_CACHE_BYTES ?= 4096
```

支持 512、1024、2048、4096、8192、16384、32768、65536 字节。生产顶层根据数据容量、路数和行长计算集合数：

$$N_{set}=B_{cache}/(2\times128).$$

缓存中的同步读接口最多返回 128 位数据。64 位 AXI 每拍传输 8 字节，完整缓存行由多个 AXI 数据拍填充。DW 和压缩 S8 矩阵输入可每拍接收 16 个元素；其他矩阵输入按请求的有效通道数接收。

```bash
make menuconfig
make capacity-show IM2COL_CACHE_BYTES=8192
make capacity-check IM2COL_CACHE_BYTES=8192
```

驱动读取硬件报告的数据容量用于卷积调度。修改输入缓存容量时，应同时检查整个 NPU 的存储预算和模型运行周期。

## 存储容量

128 字节缓存行使用 25 位地址标签。每行还保存两份 10 位窗口编号、三份 32 位使用位置、一位有效状态和三个两位来源字段，共 148 位元数据。请求队列、响应队列、预取队列及运算寄存器单独计量。

| 数据容量 | 集合数 | 标签及使用状态 | 数据与元数据合计 |
|---|---:|---:|---:|
| 0.5 KiB | 2 | 74 B | 586 B |
| 1 KiB | 4 | 148 B | 1,172 B |
| 2 KiB | 8 | 296 B | 2,344 B |
| 4 KiB | 16 | 592 B | 4,688 B |
| 8 KiB | 32 | 1,184 B | 9,376 B |
| 16 KiB | 64 | 2,368 B | 18,752 B |
| 32 KiB | 128 | 4,736 B | 37,504 B |
| 64 KiB | 256 | 9,472 B | 75,008 B |

容量工具统计展开后的 RAM、ROM、元数据、PE 和流水寄存器。`--target generic` 对应周期仿真的实现分支；`--target asic` 对应 ASIC 宏实现分支。报告同时保存 RTL 文件摘要、参数和 Verilator 版本，仅适用于相同源码与配置。

## 输入工作集

NHWC 输入的数据大小为：

$$B_{input}=H\,W\,C\,e,\qquad e=1\text{（S8）或}2\text{（S16）}.$$

例如，`16 × 16 × 16` 的 S8 输入占 4096 字节，S16 输入占 8192 字节。完整输入能否常驻还需要检查各集合内的缓存行数量。

空间索引要求输入起始地址为 128 字节整数倍，并且每像素字节数为 128 的整数倍，或为小于 128 的二次幂。对于每像素不足一条缓存行的情况，一条缓存行包含多个相邻像素；对于较大的像素，当前通道片段按空间位置选择集合。其他情况使用物理缓存行地址的 XOR 索引。

### 16 通道输入的连续行带

以下容量提示采用 C=16、dilation=1、输入起始地址为缓存行整数倍的非分组 NHWC 输入。对于有效卷积核高度 `H_eff` 和输入宽度 `W`，输入行带包含 `H_eff × W` 个像素：

$$H_{eff}=1+(K_h-1)D_h.$$

工具检查输入行起点能够到达的所有缓存行内偏移，并计算最拥挤集合的缓存行数量。下表给出最大输入宽度，每项为 S8 / S16。

| 数据容量 | 3 × 3 | 5 × 5 | 7 × 7 |
|---|---:|---:|---:|
| 0.5 KiB | 8 / 4 | 5 / 2 | 4 / 2 |
| 1 KiB | 20 / 10 | 12 / 6 | 8 / 4 |
| 2 KiB | 40 / 20 | 24 / 12 | 17 / 8 |
| 4 KiB | 84 / 42 | 50 / 25 | 36 / 18 |
| 8 KiB | 168 / 84 | 101 / 50 | 72 / 36 |
| 16 KiB | 340 / 170 | 204 / 102 | 145 / 72 |
| 32 KiB | 680 / 340 | 408 / 204 | 292 / 146 |
| 64 KiB | 1364 / 682 | 818 / 409 | 584 / 292 |

其他通道数应调用 `analyze_convolution` 并使用实际 `input_channels`。例如，24×24×32 的 S8 输入中，三行连续输入占 2304 字节，包含 18 条 128 字节缓存行。4 KiB 数据缓存共有 32 条缓存行，其容量足以保存这一行带；请求顺序和预取时机会影响实际等待时间。

对于 dilation 大于 1 的情况，提示计算包含中间间隔和全部输入列的保守行带。stride、padding、WS/IS 和 R/W 调度均可能改变缓存访问顺序。周期比较使用实际 RTL、张量地址和相同外部存储时序。

## 验证入口

```bash
make capacity-test
python3 test/conv_frontend/tools/run_rtl.py --help
python3 test/cache_pipeline/run.py --help
python3 test/window_dma/run.py --help
python3 test/ia_shared/run.py --help
```

容量测试检查数据容量、元数据位数、配置优先级和独立枚举得到的集合占用。前端测试覆盖 S8/S16、通道尾部、非整数倍地址、边界补零、stride、背压和 DMA 错误。窗口 DMA 测试检查连续请求、普通 DMA 与窗口请求并存、任务中止及随后的任务恢复。IA 共享存储测试逐项核对写入掩码、数据值、同步读取和 IA/PS 同时访问。
