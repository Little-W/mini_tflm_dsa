# NPU 完整 SoC RTL 优化与验证

## 当前状态

本轮在参考提交 `4dee27ffec4dc891daf2681379f8b3fd27fd41f2` 的现有共享存储实现上，优化了窗口描述符处理、缓存匹配、向量写回、帧调度、共享存储碰撞检查及 AXI-Lite 读回。各模块由独立任务并行处理，采用中文 RTL 注释，并保持原有公开事务周期。

完整 SoC 的同条件开源综合减少 **1,976 个逻辑 LUT 单元，约 3.21%**。功能回归、等价证明、四态检查及 FPGA/通用时钟门控检查均已通过。最终八十三份生产 RTL 文件与测量快照逐项核对一致。

目标器件为 `xc7a200tfbg484-3`，资源目标为总 Slice LUT 不超过 50,000，频率目标为 150 MHz。本轮执行环境未提供 Vivado，当前尚无新版本的布局布线结果，因此这两项物理实现目标的通过状态保留为待测量。

## 采用的 RTL 结构

### 窗口描述符与缓存

前端使用 `add_equal` 并行检查四组相邻核位置和下一空间分块的加法等式，保留完整 32 位模加法及 33 位扩展比较的行为。候选坐标及填充状态分别计算，描述符选择已经完成的结果。35 位有符号坐标和边界范围保持完整。

缓存分别计算输入请求、队首请求和下一请求的字地址匹配，再根据队列与缺失状态选择结果。`work_word_matches_q` 和 `demand_word_matches_q` 在原时钟边沿更新。生产单项队列中，`req_valid` 到匹配寄存器的局部组合路径由 7 级降至 2 级。

### 向量写回与配置检查

`vector_engine` 使用 `vector_writeback` 的字节合并配置。连续 DW 字节结果只旋转 `TILE` 个有效字节；完整数据字使用独立事务。接收请求时保存连续末地址，后续追加检查直接比较该寄存值。默认通用合并配置继续提供给其他调用方。

激活范围检查首先判断两个端点是否符合 INT8 符号扩展，再比较低八位的有符号次序。完整配置检查器的公开输出和阶段周期已经通过等价证明。

### 调度、共享存储与寄存器接口

帧调度器按最多八位一组计算列增量。生产配置的 29 位计数器分为 8、8、8、5 位，各组进位由对应低位的与归约产生，避免在完整设计中形成逐位串接的逻辑。

共享存储提前比较四对 IA 行地址，再由读写请求的优先级选择碰撞结果。端口零优先级和字节掩码保持一致。AXI-Lite 读回采用八组、每组十六个字的选择结构，保留完整地址检查、读响应周期和四态数据行为。

生产 RTL 使用算术、布尔运算和数组描述硬件，LUT、BRAM 和 DSP 交由综合工具推断。FPGA 时钟门控采用 `BUFGCE`；通用分支保留低电平锁存使能的结构，供 ASIC 流程使用。

以下两列采用同一版本 Yosys、相同 xc7 映射设置及相同生产参数。顶层 `soc_top` 包含 NPU、PicoRV32、CPU RAM、AXI 互连和 UART。

| 项目 | 参考实现 | 当前实现 |
| --- | ---: | ---: |
| 逻辑 LUT 单元 | 61,504 | 59,528 |
| 触发器 | 43,335 | 43,371 |
| DSP | 328 | 328 |
| RAMB36 | 99 | 99 |
| RAMB18 | 73 | 73 |
| CARRY4 | 4,268 | 4,235 |
| 最长寄存器间组合单元数 | 28 | 25 |

上述 LUT 数量是布局前的逻辑单元计数。50,000 的目标使用原生布局结果中的总 Slice LUT，包含逻辑、分布式 RAM 和 SRL 占用。

实际连接图的定向路径结果如下。统计从时钟控制的存储输出到同步数据或控制输入，包含 LUT、进位和选择单元；连接图已完整遍历。

| 路径范围 | 参考实现 | 当前实现 |
| --- | ---: | ---: |
| q0 描述符存储器到 `demand_word_matches_q/D` | 27 | 19 |
| q0 描述符存储器到 `work_word_matches_q/D` | 28 | 18 |
| q0 描述符存储器到任意前端终点 | 28 | 21 |
| 完整描述符队列到前端 | 28 | 23 |
| 前端及其缓存内部 | 28 | 25 |

两个固定匹配终点的当前路径均不经过 `CARRY4`。参考实现中，连续的地址加法和填充范围比较共使用十一个 `CARRY4` 单元；当前实现通过并行检查加法等式、提前计算候选填充状态和选择缓存匹配结果缩短了这些路径。

当前最长路径从 `row_wrap_q` 到缓存 `work_request.in_range`，需求队列保存的同一范围标志也存在相同深度的路径。其经过 `next_row_addr = row_base_addr + (row_wrap ? row_wrap_bytes : row_step_bytes)` 的地址加法，以及 `req_addr >= base_q` 的范围比较，共包含十一个 `CARRY4` 单元和十四个 LUT。此处是当前连接图中最深的组合路径，具体器件延迟及布线延迟由原生实现结果确定。

完整资源、路径分组、参数和源码摘要见 [SoC 测量数据](data/npu_soc_optimization_20261121.json)。

## 复现入口

完整 SoC 开源综合：

```sh
python3 scripts/fpga/open_fpga_synth.py --cases soc_top --out build/open_soc_150mhz
```

主要功能回归：

```sh
python3 test/fpga_integration/run.py --out build/fpga_npu_150mhz --jobs 2
python3 test/vector_engine/run.py --out build/vector_pe8_150mhz --pes 8 \
  --tile 16 --bus-width 64 --cache-line-bytes 16 --cache-sets 128 --shared-storage --xilinx
python3 test/vector_engine/run.py --out build/vector_pe16_150mhz --pes 16 \
  --tile 16 --bus-width 64 --cache-line-bytes 16 --cache-sets 128 --shared-quant --shared-storage --xilinx
```

各独立模块目录保存形式证明、模块综合与功能检查的入口：`test/frontend_window_timing`、`test/cache_match_timing`、`test/vector_writeback_area`、`test/vector_config_ranges`、`test/scheduler_column_depth`、`test/shared_ram_collision` 和 `test/axil_read_mux`。

原生 Vivado 命令显式采用上传报告的综合策略与生产容量，核心时钟为 150 MHz：

```sh
NPU_CONFIG="$PWD/config/npu_fpga.mk" \
VIVADO_SYNTH_STRATEGY=Flow_AreaOptimized_high \
VIVADO_SYNTH_DIRECTIVE=AreaOptimized_high \
VIVADO_RUN_IMPL=1 VIVADO_JOBS=8 \
vivado -mode batch -source scripts/fpga/vivado_synth_fpga.tcl \
  -tclargs build/vivado_150mhz xc7a200tfbg484-3 16 4 65536 0
```

入口保存完整时序汇总、总 Slice LUT、分模块最差路径、组合级数分布、高扇出信息和 DCP。布线目录为 `build/vivado_150mhz/reports/routed`。`measurement.json` 分别记录总 Slice LUT 是否不超过 50,000，以及 150 MHz 建立时间和保持时间是否通过。
