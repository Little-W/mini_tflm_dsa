# 开源 FPGA 综合

本项目使用 Yosys、Slang 和 ABC 将 RTL 映射到 Xilinx 7 系列器件资源。该流程用于比较模块的 LUT、寄存器、DSP 和存储器资源，并检查组合逻辑的级数。

## 环境与运行

在 Python 环境中安装 `pyosys`：

```sh
python3 -m pip install pyosys==0.71.post40
make open-fpga-synth
```

默认综合 16×16 脉动阵列、七 bank 共享存储器、卷积缓存 RAM、向量写回模块和完整向量计算单元。`npu_top` 可用于完整 NPU 综合。可以指定需要综合的模块及输出目录：

```sh
make open-fpga-synth OPEN_FPGA_SYNTH_CASES="array vector_engine" OPEN_FPGA_SYNTH_DIR=build/open_fpga_synth
make open-fpga-synth OPEN_FPGA_SYNTH_CASES=npu_top OPEN_FPGA_SYNTH_DIR=build/open_fpga_synth
```

结果目录中的 `summary.json` 保存工具版本、参数、源码 SHA-256、单元数量、组合逻辑级数及最长组合路径的单元序列。各模块子目录包含综合脚本、综合日志和映射网表。阵列的开源综合使用逻辑等效的权重使能直连；完整 NPU 综合使用等效的 `LUT1` 功能模型。

## 参考结果

使用 Yosys 0.71、Slang、ABC 和 `synth_xilinx -family xc7`，基于 `c3712e54` 的 RTL 得到以下模块映射结果，各模块的源码摘要记录在参考数据中。LUT 列统计映射网表中的 LUT 单元；分布式 RAM 单独列出，实际器件占用需要计入其对应的 LUT 资源。

| 模块 | 配置 | LUT 单元 | 触发器 | RAMB36 | DSP48E1 | 组合逻辑最大级数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 脉动阵列 | 16×16，INT16 | 4,130 | 11,807 | 0 | 256 | 2 |
| 共享存储器 | 7 bank，每 bank 8 KiB | 5,486 | 41 | 14 | 0 | 9 |
| 向量写回 | 16 通道，64 位总线 | 674 | 55 | 0 | 0 | 10 |
| 卷积缓存 RAM | 256 个 32 位字，64 位写入 | 40 | 1 | 0 | 0 | 1 |
| 向量计算单元 | 8 个 PE，64 位总线 | 15,392 | 6,867 | 0 | 14 | 23 |
| 完整 NPU | 16×16 阵列，64 位总线 | 69,871 | 45,171 | 85 | 390 | 35 |

向量计算单元另使用 48 个 `RAM64M`，卷积缓存 RAM 使用 2 个 `RAMB18E1`；完整 NPU 另使用 89 个 `RAMB18E1`、48 个 `RAM64M` 和 192 个 `SRL16E`。完整资源分类和源码摘要见 [参考数据](data/open_fpga_reference.json)。

组合逻辑级数由映射网表中的 LUT、进位单元、选择器、反相器、异步分布式 RAM 及移位寄存器 RAM 构成的有向图计算；触发器、块 RAM 和 DSP 作为路径边界，分布式 RAM 的读地址与读输出按保守依赖处理。该指标用于比较逻辑结构，不包含器件布线延迟。150 MHz 目标使用完整 SoC 的 Vivado 时序报告检查。

## 资源和时序目标

完整 SoC 的资源目标为少于 50,000 LUT。开源流程对 NPU 单独综合，因此需要为处理器、总线、寄存器接口和其余 SoC 逻辑保留资源。按照现有完整 SoC 综合中的模块分布，可先将开源 NPU 映射结果控制在 40,000 个 LUT 单元以内，并分别检查分布式 RAM、移位寄存器 RAM、DSP 和块 RAM 数量。该数值为优化规划，后续应根据相同配置的完整 SoC 器件映射结果调整。

组合逻辑级数用于识别较深的路径，并比较相同模块修改前后的结构。评估 150 MHz 时，需要对完整设计施加 6.667 ns 时钟约束，并使用目标器件的单元和布线延迟进行时序分析。若使用支持目标器件的开源布局布线工具，应记录器件型号、封装、速度等级、时钟约束和工具版本，并检查时序报告中的最差建立时间裕量。
