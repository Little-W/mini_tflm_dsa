# DMA 参数、矩阵排列与起始地址

共同算子采用同一份数学张量、INT8 输入和权重、INT32 偏置，以及除以 32 后按最近偶数舍入的 INT8 输出。两侧均使用 16×16 主阵列、32 位外部数据接口，以及相同的存储器服务：读数据每两个周期返回一拍，空闲时首拍延迟为三个周期；读写独立，外部一次服务一个写事务。共同 GEMM 的矩阵排列与起始地址设置在计时之前完成。NPU 从 `calc_start` 接受完整配置时开始计时；Gemmini 从第一条配置命令开始，直到最终 `FENCE` 确认全部事务完成。两者均包含传输、计算和写回，排除主机指令执行时间。完整比较及来源摘要保存在 [gemmini_dma_parameters.json](gemmini_dma_parameters.json)。

### 四个完整配置

Gemmini 的 DMA 最大事务长度设置在官方 `GemminiArrayConfig.dma_maxbytes` 中，并同步设置外部 AXI 的 `TransferSizes`。固定版本的官方参数头仍将软件 `MAX_BYTES` 定义为 64；硬件 `LoopMatmul` 与 `LoopConv` 按实际 `dma_maxbytes` 展开载入，OS 软件按官方参数头生成命令。硬件参数和软件参数分别保存在构建清单与命令元数据中。

| Gemmini scratchpad / accumulator | 最大 DMA 事务 | 共同 GEMM 总周期 | NPU 总周期 | Gemmini 周期 / NPU 周期 | NPU 更快的形状数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 / 16 KiB | 64 B | 513,838 | 468,131 | 1.09764× | 31 / 31 |
| 32 / 32 KiB | 64 B | 513,902 | 468,131 | 1.09777× | 31 / 31 |
| 256 / 64 KiB | 64 B | 512,935 | 468,131 | 1.09571× | 31 / 31 |
| 256 / 64 KiB | 128 B | 505,972 | 468,131 | 1.08083× | 31 / 31 |

NPU 的主数据 RAM 为 66,496 B，另有 4 KiB 窗口缓存；共同 GEMM 不使用该窗口缓存。Gemmini 的主阵列操作数为 8 位，NPU 的通用操作数数据通路为 16 位，两者在这些测试中处理相同的 INT8 数值。上述比较分别保留存储容量、数据通路位宽和辅助计算单元的差异。

128 B 配置同时搜索三种官方支持的矩阵排列，以及按 64 B、128 B 边界放置张量的两种方式。普通排列测试 WS 与 OS，A 转置、B 转置分别测试 WS。共考虑 32,542 个合法候选，其中 1,851 次完整 RTL 执行均通过数值、非输出内存、总线响应和实际读取流量检查；其余候选由已验证的传输周期下界或当前最短完整执行时间排除。选出的 31 份命令再次独立执行，225,375 个输出字节全部正确。其中 24 项采用 64 B 起始边界，7 项采用 128 B 起始边界。

最大事务长度与起始地址会共同影响实际传输。官方读包选择器优先选择能够覆盖更多当前有效字节的包，因此较大的上限可能增加额外读取。以相对周期差最小的形状 `M=9,N=256,K=256` 为例，Gemmini 采用 B 转置、WS 分块 `(1,5,16)` 和 128 B 起始边界，运行 36,101 周期；NPU 采用双操作数打包、WS、`R=1,W=16`，运行 35,980 周期。双方均读取 68,864 B，NPU 少 121 周期，周期减少 0.33517%。

这条 Gemmini WS 命令包含首 10 个配置周期；从第一次循环启动至完成为 36,091 周期，NPU 仍少 111 周期，减少 0.30756%。30 个具有 WS 循环启动时间的共同形状都保持这一比较方向。一个采用 OS 的形状直接提交执行指令，循环启动时间记为 `null`。

### 更大事务长度的已验证形状

固定官方实现的读响应完成字节数使用 8 位字段，单个响应的有效载荷范围为 0 至 255 B。256 B 和 1024 B 配置的有效形状按实际地址、分组及每次响应载荷分别检查。交付数据保留通过完整输出与内存检查的记录：256 B 覆盖 26 个形状，1024 B 覆盖 19 个形状。每个记录包含原始配置、命令、输入内存、实际输出、运行日志及其硬件清单；这些配置的 31 项总周期字段为 `null`。

这些有效单项全部加入逐形状最短参考。最终 NPU 的 31 个共同 GEMM 均快于该集合中的每一个有效实测结果。四个完整配置使用同一组 31 个形状计算总周期；较大事务配置只进行已验证形状的逐项比较。

### 原生 Conv 与 DW

以下测试直接提供图像，硬件窗口地址生成、边界补零和数据复用进入计时。Gemmini 显式启用 `has_loop_conv`、`has_dw_convs` 和 `has_first_layer_optimizations`，由官方 `tiled_conv_auto()`、`tiled_conv_dw_auto()` 驱动。当前官方接口使用 `LoopConv`，独立 `hasIm2Col` 模块关闭；统计记录实际 `LOOP_CONV_WS` 与 depthwise 启动次数。

| 原生算子 | NPU 周期 | 四个完整 Gemmini 配置中的最短周期 | Gemmini 周期 / NPU 周期 |
| --- | ---: | ---: | ---: |
| Conv 3×3，stride 2，96×96×3 → 48×48×8 | 55,335 | 85,266 | 1.54091× |
| DW 3×3，stride 1，48×48×8 | 44,018 | 166,080 | 3.77300× |
| DW 3×3，stride 2，48×48×8 → 24×24×8 | 11,461 | 113,348 | 9.88989× |

Gemmini 128 B 配置的三个周期分别为 93,906、172,232、113,348；把张量起点从 64 B 边界改为 128 B 边界后，这三个结果保持一致。普通 Conv 在 128 B 配置下读取 127,496 B，而同容量 64 B 配置读取 109,496 B，较大的事务上限增加了该任务的读取量。

原生矩阵存储的辅助测试保留双方各自的普通矩阵接口排列。NPU 使用 AUTO 调度，Gemmini 在这一排列下搜索官方支持的合法分块。NPU 的 31 项总周期为 530,569，相对三个 64 B Gemmini 配置均有 22 项更快。该辅助组与允许打包和转置排列的主要 GEMM 组分别报告。

### 统计定义

有效 MAC 吞吐率比例采用逻辑 MAC 数除以实际计算单元数与完整任务周期。主阵列按 256 个 MAC 单元计算，NPU 的 DW 路径按 8 个向量 MAC 单元计算。这一指标包含传输、配置和写回时间。上述 `M=9,N=256,K=256` 任务的 NPU 与 Gemmini 比例分别约为 6.40356% 和 6.38209%。
