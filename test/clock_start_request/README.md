# 时钟唤醒后的启动请求

启用时钟门控时，`npu_axil_top` 保存软件启动请求，在唤醒间隔结束后持续给出请求有效信号。计算单元的 `sa_ready` 与请求有效同时为真时，控制器清除待处理请求。等待就绪期间时钟持续运行。

完整 NPU 的各任务接收端在请求有效与就绪同时为真时保存配置。`GEMMORA_INT8_PROFILE` 使用其已有的接收脉冲形式。关闭时钟门控时，启动输入直接使用原控制脉冲。

## 验证

`run.py` 提取实际 `npu_axil_top.sv` 的全部唤醒控制过程、启动表达式和时钟使能表达式，与参考提交 `6f70ce67` 比较。两种配置和两种时钟门控参数共四组状态证明通过，合计 64 个比较位。所有外部事件保持自由，完成有效和完成握手独立变化。

二态与四态时序比较覆盖 200,006 个周期和 7,200,216 次输出位比较，检查完整控制状态、实际启动接收、时钟使能及精简配置的启动脉冲。

时钟相位测试使用实际 `npu_axil_top`，子模块保留公开接口并由测试提供控制事件。测试检查高、低时钟相位复位、唤醒间隔、延迟就绪、一次接收、AXI 应答等待以及完成后的时钟关闭，共观察 41 个有效时钟上升沿。

接收周期和时钟使能保持一致。完整 SoC 的组合逻辑级数由相同版本的整机报告统计。

## 复现

```sh
python3 test/clock_start_request/run.py --out build/clock_start_request
```

`validation.json` 保存源码校验值、四组证明和时钟相位检查结果。
