# DMA 错误上报寄存

`axi_block_dma_arbiter.p_register_bus_error` 控制总线错误的上报周期，默认值为 `0`。

参数为 `0` 时，公开输出、内部仲裁状态和 DMA 实例端口均保持直接上报的行为。参数为 `1` 时，仲裁器在错误响应握手的当前周期生成 `local_abort`，停止授予新命令、取消等待交付的读描述符，并向实际 DMA 传递中止状态。已经接收的读上下文和写事务继续使用原有排空逻辑。`bus_error` 在下一周期报告该事件，覆盖物理 R/B 错误以及读写完成错误。

顶层启用该参数后应直接接收这一寄存输出。任务完成条件必须保证已接收事务完成排空，并保留总线错误的结果优先级。

## 形式验证

```sh
python test/dma_registered_error/run_formal.py \
  --reference-ref 9a6437f48722b3f53d4084b48c72cfb1d4b1fa5a \
  --out build/dma_registered_error/formal
```

脚本读取修改前的仲裁器源码和当前源码，保持实际 DMA 的完整端口边界。DMA 输出及外部请求均为自由输入，所有仲裁寄存状态、公开输出和发送至 DMA 的端口都参与比较。

寄存模式的参考系统由原仲裁器、同周期总线错误中止反馈和一级错误报告寄存器组成。这一参考结构明确检查本地中止的时刻及报告周期。默认模式直接比较两版设计。

验证包括 32、64、128 位总线和量化客户端开启、关闭的 FPGA 配置，以及 64 位总线的 ASIC 配置。两种参数模式共 14 组，合计证明 30,622 位等价关系。

## 实际 DMA 仿真

```sh
python test/dma_registered_error/run.py \
  --reference-ref 9a6437f48722b3f53d4084b48c72cfb1d4b1fa5a \
  --verilator verilator-modern \
  --out build/dma_registered_error/simulation
```

仿真包含实际 `axi_dual_block_dma`、线性 DMA、读取保护和写入保护模块，并实例化原仲裁器作为逐周期比较对象。81 个公开输出均参与比较，其中 `bus_error` 按一个周期的报告关系比较，其余输出保持逐周期一致。

32 位和 64 位总线各执行 21 项正常及外部中止检查、10 项错误场景和 10 项错误后恢复检查。场景覆盖五个读请求方、最后一个读响应出错、连续错误响应、正常读完成与写错误同时到达、外部中止与错误同时到达、等待交付描述符的取消，以及多个已接收写事务的排空。每种配置比较 585 个有效运行周期，完成 1,592 项行为检查，并启用 C++ 未定义行为检查器。

`measurement.json` 保存源码摘要、通过的验证结果及各报告摘要。测试完成后保留可执行文件和日志，删除可重新生成的编译中间文件。
