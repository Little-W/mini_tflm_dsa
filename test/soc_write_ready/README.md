# SoC 写入接收条件

`soc_axi_interconnect` 对当前写地址和已保存写目标分别计算外设接收条件，再由写事务状态选择结果。采用已保存写地址时，RAM 数据接收只检查已保存的所有者和事务状态。允许地址与数据同时开始时，使用当前仲裁结果。

每个外设的选择位与对应接收信号先独立组合，再归并完整接收条件。含未知值或高阻值的控制继续使用逐项选择表达式，保持四态仿真的状态和输出行为。公开接口、同步事件和存储容量保持一致。

## 验证

```bash
python3 test/soc_write_ready/run.py --out build/soc_write_ready --verilator verilator
```

验证包含 16 种参数配置的完整互连状态及输出证明；32、40、64 位地址与 32、64 位总线；不同 RAM 容量、地址窗口和在途事务数量；两种写地址重叠配置。外部输入自由变化。

普通编译与 `SYNTHESIS` 编译分别检查两种重叠配置，共比较 80,004 个四态周期。六组并发事务检查覆盖 CPU 与 NPU 写入、独立地址和数据握手、窄写入、反压和错误响应。结果保存在 `validation.json`。

生产 SoC 在 CPU 写地址缓冲中保存目的标志。使用 `--predecoded` 可检查该模式下的完整互连，输入关系为目的标志与当前缓存地址的译码相同；`test/soc_write_metadata/run.py` 独立证明两个存储槽在任意接收和发送序列下保持这个关系。
