# 偏置驻留范围比较

`bias_loader_buffer` 同时比较两个银行的起点与完整扩展后的末端，独立保留装载请求和当前执行请求。`p_share_load_index` 为 1 时，两个请求采用相同索引。

末端关系为 `request_base + request_count <= bank_end_q`。两个请求操作数先扩展一位，再与银行末端的按位取反结果进行三操作数压缩。压缩结果的最高进位直接表示请求末端越界，`parallel_prefix_add` 只保留实际消费的进位计算。起点采用直接无符号比较。双银行容量、同步存储行为、有效条件和接口周期均保持原有功能。

## 检查方法

`run.py` 从两份实际缓冲区源码提取全部驻留表达式，并确认表达式之外的代码相同。参考版本和当前版本分别使用各自的公共加法器。形式验证不限制请求索引、请求长度、银行起点、银行末端或银行有效标志。

```bash
python test/bias_range_carry/run.py \
  --reference-root build/bias_range_carry/reference \
  --source-root . \
  --out build/bias_range_carry/formal_current
```

计数位宽覆盖 1、2、3、8、12、28、29、32，索引共享参数覆盖 0 和 1。四态检查同时比较两种共享配置的全部 16 个结果位，包含逐位 X/Z 扰动、全零、全一和随机输入。结果必须逐位相同。

## 已完成结果

- 16 组完整输入形式验证通过。
- 267,648 组四态输入、4,282,368 次结果位比较通过。其中 226,416 组包含未知输入，146,483 组产生未知结果。
- 完整偏置加载器的 392 个数值场景通过，合计 193,571 个周期、880 条 DMA 命令。覆盖 WS/IS 模式、32/64 位总线、1 至 32 个块的银行容量；该数值测试采用 12 位计数器，生产使用的 29 位计数器已包含在完整输入证明中。

采用相同公共加法器，对完整 `bias_loader` 的生产参数 `SIZE=16`、`BUS_WIDTH=64`、`COUNT_WIDTH=29`、`GROUP_BLOCKS_MAX=32` 进行映射：

| 项目 | 修改前 | 当前 |
|---|---:|---:|
| LUT | 1,182 | 1,243 |
| 寄存器 | 1,227 | 1,227 |
| 模块内部最长组合单元数 | 14 | 9 |
| 到 `bias_valid` 的最长组合单元数 | 13 | 7 |
| 到 `bias_group_valid` 的最长组合单元数 | 14 | 8 |

源码摘要、参数、检查结果和完整路径文件记录在 `validation.json`。
