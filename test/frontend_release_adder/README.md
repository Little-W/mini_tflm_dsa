# 缓存接收前的普通行偏移加法

`conv_im2col_frontend` 使用一次普通加法，计算 16 位行坐标与 17 位配置偏移的 18 位和。行释放元数据仍由已有的缓存接收寄存器保存，变量右移在该寄存器之后完成。配置准备、限幅判断、元数据格式及缓存控制保持相同。

## 自由输入等价

```bash
python test/frontend_release_adder/run_formal.py --out build/frontend_release_adder_formal
```

参考提交为 `e31241c7`。脚本从两版实际 RTL 提取运算，并检查加法范围之外的前端代码及完整缓存代码相同。

- 33 位自由输入覆盖全部 16 位行坐标和 17 位偏移值，证明 18 位和逐位相同。
- 164 位自由输入覆盖请求与预取选择、配置算术、限幅和禁止释放行为，证明两路共 64 位元数据相同。

两项检查均通过；输入取任意已定义的二进制值，无额外范围假设。所有状态更新和寄存使能保持相同，因此运算等价适用于原有接收、排队和消费周期。

## 实际窗口协议

```bash
python test/frontend_release_adder/run_protocol.py \
  --out build/frontend_release_adder_protocol --verilator verilator-modern
```

脚本复用实际 FPGA 窗口模型，前后版本共用同一组依赖，启用断言及未定义行为检查。原有 15 类窗口场景通过，包含背压、读取错误、任务取消、配置等待、普通读取并发及复位恢复。64 组行释放配置共完成 1,536 个请求、12,967 个数值比较和 85,867 个逐周期输出比较，记录全部相同。

连续命中场景的 128 个请求、512 个返回拍使用 1,534 个周期，最大返回间隔为 3 个周期，最大在途请求数为 4，前后相同。

## 完整前端资源与组合路径

```bash
python test/frontend_release_adder/measure.py --out build/frontend_release_adder_measurement
```

两版均使用普通 RTL 算术推断和相同综合选项，参数为 32 位前端内部 AXI、16 列、4 个输出通道、128 个缓存集合、2 路、16 字节缓存行。

| 指标 | 分组加法 | 普通加法 |
|---|---:|---:|
| 逻辑 LUT | 12,698 | 12,609 |
| 分布式 RAM 名义 LUT 位置 | 240 | 240 |
| FF | 6,046 | 6,046 |
| DSP | 43 | 43 |
| RAMB18 | 23 | 23 |
| 坐标及配置到缓存元数据寄存器 | 8 级 | 9 级 |
| 缓存元数据寄存器到消费存储 | 5 级 | 5 级 |
| 完整前端最长路径 | 15 级 | 16 级 |

普通加法减少 89 个逻辑 LUT 和 8 个 CARRY4，两段行释放路径均不超过 9 级。当前完整前端的最长路径位于 `pf_distance_q` 到 `pf0_x`，不经过行释放加法。整机路径及实际器件时序需要结合对应完整综合报告检查。源码摘要、路径详情和结果保存于 `measurement.json`。
