# 权重加载描述符选择

受管传输活动期间，请求资格保持无效，因此活动描述符直接由传输状态和管理模式选择。普通加载继续检查其完整请求资格。端口描述符和突发长度使用同一个选择结果，配置接收、发出请求及数据返回的时钟边沿保持一致。

控制器将完整发出计数的高位零值独立归并，用于有界待处理数量的回绕检查。列尾比较保留逐位模加等式，由综合工具合并相邻位的比较逻辑。

## 验证

```bash
python3 test/kernel_port_selection/run.py --out build/kernel_port_selection/check
python3 test/kernel_port_selection/measure.py --out build/kernel_port_selection/measurement
```

请求资格的检查直接提取生产源文件中的组合过程。完整加载器形式检查包含四种分块、计数和总线配置，比较全部共有状态及公开输出，外部输入没有附加限制。四态检查穷举 4,194,304 种控制组合，并同时检查描述符位的 16 种数据组合，共完成 67,108,864 次描述符位比较。

16 个元素一块、29 位计数、64 位总线的完整加载器使用 2,921 个逻辑 LUT。预取状态到突发长度输出边界为 7 级，发出计数到待处理状态为 10 级，完整加载器最长寄存器间路径为 11 级。完整 SoC 结果单独保存。

`validation.json` 保存完整状态与四态检查结果，`measurement.json` 保存源文件摘要、资源统计和实际连接路径。
