# 向量写回字节银行验证

`vector_banked_writeback` 位于 `rtl/npu/conv/vector_engine.sv`，使用普通同步读写数组保存两组结果。每个字节银行在一个周期接收一个字节，各银行共同构成一个总线数据字。待发送结果与当前事务使用不同的存储组，事务发布时交换组号。

## 接收与发送

生产方保持 `request_valid`、地址、长度、数据和结束标记，直到 `request_ready` 有效。一个请求按总线宽度依次写入银行，最后一个数据字保存时完成接收；长度不超过总线字节数的请求可在一个周期完成接收。字节模式从各个 32 位元素中提取低字节，超出 `TILE` 的请求字节填入零。完整字模式保留所有输入字节。

连续地址的请求可合并到同一组中。容量、结束标记、非连续地址或 `flush` 触发发送。`p_coalesce_bytes_only=1` 时只合并字节结果；参数为零时也支持完整字结果合并。

同步读取的数据经过按字节旋转后发送。事务的数据阶段在 `src_wready` 持续有效时每个周期发送一拍，首拍和末拍由字节使能描述有效位置。等待授权和数据背压期间，配置与负载保持稳定。部分接收请求取消时，其未确认字节不进入有效长度；已确认的待发数据继续完成发送。

## 运行

```sh
python test/vector_banked_writeback/run.py \
  --source-root . \
  --out build/vector_banked_writeback \
  --verilator verilator \
  --jobs 1
```

测试直接提取生产模块，通过公开请求和总线接口检查每个已接收字节的地址与内容。报告保存模块、测试文件和日志的 SHA256。

验证配置包括 `TILE=1、2、3、16、64`，总线宽度 `32、64、128` 位，以及两种请求合并参数。检查所有首拍字节位置、从一个字节到完整容量的请求、字节补零、32 位地址回绕、授权等待、数据背压、部分请求取消、错误响应与后续请求恢复。连续发送检查要求每个数据周期均有有效输出。

完整引擎验证使用 `test/vector_engine/run.py` 的独立整数参考实现，并启用 `--rtl-assertions`、`--stable-stimulus` 和 `--check-weight-prefetch`。生产配置为 `TILE=16、PE_COUNT=8、BUS_WIDTH=64、WINDOW_LANES=8`，使用七个共享存储银行和独立向量量化。共享量化分支使用 32 位总线及四路窗口响应进行验证。两种配置均覆盖向量 INT8/INT16 输入、INT32 结果、深度卷积、池化、Add 和 Softmax。
