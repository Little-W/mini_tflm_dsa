# 可选分段加法推断

`parallel_prefix_add` 的 `p_dsp_split_width` 默认值为 `0`。非零值指定低段位宽，两个数据段均为 1 至 23 位时，综合分支使用普通加法表达式和 `use_dsp="simd"` 属性。其余参数组合继续采用现有分组加法或进位选择结构。输入和输出接口、组合延迟的周期属性、完整结果位宽及最高进位保持一致。

低段的两个操作数和加法结果按 `i_carry` 同时取反。定宽恒等式 `~(~a + ~b) = a + b + 1` 将输入进位保留在两操作数加法中。高段首先独立相加，再根据低段进位和高段各位的传播条件逐位修正。每个部分和都包含最高进位。

`p_preserve_groups=1` 时，高段保留四位传播组及其并行前缀。每位结果直接组合完整组前缀、最多三位组内传播条件和低段进位。

`parallel_prefix_native_sums` 将两个普通加法表达式及其输出端口保留在同一组合模块内，两个输出端口均携带算术推断属性。外层 `parallel_prefix_add` 继续展开，常量输入进位的取反编码和未使用结果可以正常简化。只有内部部分和模块保留层次；其完整输入、结果位宽和组合周期属性均不变。

两个部分和经宽度优化后的真实位宽应属于相同的 SIMD 分组。对于当前工具的双 24 位加法推断，两部分和均保留 13 至 24 位时可以配对；如果常量传播使其中一段缩短至另一分组，需重新测量实际推断结果。32 位建议以 16 位拆分，33 位建议以 17 位拆分，35 位建议以 18 位拆分。具体实例是否启用应根据完整模块的资源和路径结果确定。

## 验证

```sh
python test/parallel_prefix_dsp/run.py --out build/parallel_prefix_dsp
```

`--source-root` 可指定待验证源码目录，测试模型和映射流程仍由当前测试脚本提供。

脚本执行以下检查：

- 60 组参数的无输入约束组合证明，覆盖 1 至 64 位、分段边界、传播组保持选择及回退分支，比较全部和值及最高进位。
- 每组参数 4096 次四态输入比较，检查普通仿真的未知值传播。
- 32、33、35 位各自使用可变进位、常量进位 0 和常量进位 1，执行完整 FPGA 映射。
- 展开工具提供的完整 Xilinx 器件模型，证明映射后的所有输出与两级寄存的数学加法无限时序等价，覆盖被综合吸收到 DSP 内的寄存器。
- 记录经过 DSP 和所有组合单元的完整寄存器路径，保存源码、模型及映射结果摘要。

当前验证的 9 个映射配置均使用一个 DSP，完整寄存器路径为 4 至 6 级。验证结果记录在 `validation.json`。这些结构指标用于筛选实现，150 MHz 时序仍由目标器件的实现时序报告评估。
