# 有序窗口 DMA 验证

测试实例包含生产使用的 `axi_block_dma_arbiter`、窗口描述队列、im2col 前端、共享窗口缓存和 AXI 读取模块。32 位 AXI 存储模型提供数据，独立 NHWC 模型计算 S8 与 S16 输入的期望值。窗口访问可以使用任意空间坐标，响应保持请求顺序和两位目标标签。

```sh
python3 test/window_dma/run.py --out build/window_dma --jobs 2
python3 test/window_dma/run.py --fpga --out build/window_dma_fpga --jobs 1
```

验证覆盖以下行为：

- 暂停响应接收后，描述队列可以保留四个已接受的请求。
- 连续驻留数据包含 128 个描述、512 次响应和 2048 个有效元素；窗口内相邻响应及描述符边界均要求最多相隔三个周期，同时记录这两类实际间隔与连续返回次数。
- S8 的 256 个单拍窗口返回 1024 个元素，要求每周期返回，总跨度为 256 个周期，连续返回次数为 255。
- S16 的 128 个单拍窗口返回 256 个元素，要求每周期返回，总跨度为 128 个周期，连续返回次数为 127。
- 普通读取与窗口请求同时出现时，普通读取优先；授予准备和保持期间，窗口请求继续等待。测试还检查普通授予保持三个周期后启动的行为。
- 窗口请求经过一个周期的寄存授予后接受，连续窗口描述可以在相邻周期接受。已保存的窗口授予优先完成，随后到达的普通读取请求在其后接受。
- 队列仍有未完成窗口时，请求间隔保留窗口授予；出现其他可服务请求时，下一边沿转交授予。队列排空、任务取消或重新配置时释放授予。
- 尚未接受的窗口授予可以由请求撤回、中止或配置请求取消；取消后没有新增响应或残留的忙碌状态。
- S8 与 S16 的任意空间和归约坐标、未对齐张量、通道尾部、填充、随机 AXI 等待及响应背压。
- 读取错误，以及长度为 0、17、32、33 的非法描述；每个已接受的描述均返回一次带原标签的终止错误响应。
- 配置更新等待四个已接受的窗口描述全部完成。
- 首个读取地址暂停期间，以及仍有多个窗口描述等待完成的最后 RLAST 周期，配置请求保持等待。
- S8 与 S16 各自在四个描述尚未完成时复位，随后重新配置并校验新任务的数值结果。

前端准备项支持同周期提交与接收，并保存与描述符对应的数据字。执行中的窗口最后一次缓存响应可以供相同数据字的下一窗口使用。窗口队列允许准备、执行及输出保存三个位置各持有一项已发送描述符。`--single-response-interval` 和 `--descriptor-response-interval` 可显式选择对应测试配置，默认值分别为 1 和 3；正式结果同时记录实际使用的参数。缓存自身的每周期读取能力由 `test/cache_pipeline` 单独检查。

`--fpga` 启用生产条件编译、RTL 断言与 C++ 未定义行为检查。综合推断相关功能模型由官方器件库提供，观察模块保留独立的条件编译分支。构建记录同时保存源文件和递归引用的头文件摘要。

每个有效返回元素均与有符号输入偏移修正后的期望值比较。测试同时检查标签、列位置、掩码、最后响应标志、背压期间的数据稳定性、张量地址范围和 4 KiB 边界。`summary.json` 保存源码摘要、可执行文件摘要、性能检查参数及完成场景；复位取消数量与完成数量分别统计。

使用 `--reference-ref` 时，脚本将指定 Git 版本的 RTL 保存到独立目录，使用相同测试程序和输入再次运行。`resident_stream.csv` 记录连续驻留流的每周期请求、响应、AXI 事务及忙碌状态，两份文件必须完全一致。

`test/vector_engine` 继续验证 DW、Pool、Vector、Add、Softmax、量化、输出写入及完整输出存储内容。
