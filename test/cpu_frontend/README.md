# PicoRV32 前端结构与检查

CPU 采用执行控制器和独立前端。两者通过 `picorv32_frontend_pkg` 中的打包请求与响应传送信息，存储访问、译码和执行保持原有周期关系。

| 文件 | 功能 | 行数 |
| --- | --- | ---: |
| `rtl/soc/picorv32_npu.v` | 寄存器、算术运算、执行状态、中断和协处理器控制 | 1457 |
| `rtl/soc/picorv32_frontend.sv` | 存储握手、预取、压缩指令拼接、指令译码与执行记录 | 984 |
| `rtl/soc/picorv32_frontend_pkg.sv` | 同一时钟域内的请求和响应字段 | 118 |

前端读取控制器已经保存的访存请求、地址操作数和译码使能。外部读取完成时保存数据，压缩指令在该接收边沿补齐译码所需字段。详细译码使用控制器提供的使能，伪译码请求使用已经保存的指令。复位、异常停止和当前存储请求完成的优先次序由原有状态更新条件确定。

全部模块端口和打包字段具有中文功能说明。前端声明集中在参数与局部数据部分，符号扩展和寄存器编号转换显式指定目标位宽。

## 功能检查

形式检查比较完整 CPU 的外部接口及内部状态。测试程序将前端中具有明确对应关系的状态名称转换为原有名称，然后进行逐位等价证明。外部输入没有附加限制。

| 配置 | 已证明位数 |
| --- | ---: |
| 生产配置，32 个寄存器，双端口，迭代乘除法 | 3327 |
| 压缩指令、中断和 64 位计数器 | 3712 |
| 两周期 ALU 和两周期比较 | 3332 |
| 16 个寄存器，单端口，关闭乘除法和计数器 | 1724 |

Icarus Verilog 12 的四态执行检查分别从 `0x00000000` 和 `0xfffff000` 开始。每次运行完成 4898 个周期、717 次取指、720 次存储事务和 3258 次等待期间请求保持检查；控制、存储事务与预告请求逐周期一致。Verilator 5.48 的完整 CPU 语法检查通过，报告的警告和错误均为零。

```bash
python test/cpu_frontend/run.py --out build/cpu_frontend
```

结果和输入文件摘要保存在 `validation.json`。

## 独立 CPU 综合

两种实现均使用生产 CPU 参数、普通 RTL 输入和相同的 ABC9 设置。映射延迟目标为 6667 ps，连线延迟参数为 300 ps。综合完成后展开所有已经映射的子模块，再统计寄存器间路径。

| 项目 | 参照提交 `8b3728c0` | 当前前端结构 |
| --- | ---: | ---: |
| 逻辑 LUT | 1643 | 1635 |
| 分布式 RAM 的名义 LUT 位置 | 48 | 48 |
| 布局前 LUT 合计 | 1691 | 1683 |
| 触发器 | 1003 | 1003 |
| DSP | 1 | 1 |
| 最长寄存器间组合路径 | 11 | 10 |
| 组合路径图完整性检查 | 通过 | 通过 |
| 映射网络等价检查 | 通过 | 通过 |

`measurement.json` 保存参数、资源、源码摘要及检查结果。上述数值属于独立 CPU 综合结果；完整 SoC 资源与器件工作频率由对应的整机综合和布局布线结果给出。
