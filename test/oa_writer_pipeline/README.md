# 输出写回控制的周期预计算

## 当前结构

`oa_writer` 使用状态机已有的准备周期计算下一块信息。行列索引、组起点和已保存的配置在请求、启动及写入状态中保持稳定，寄存的中间值按以下顺序使用。

| 状态 | 已有效的结果 | 本周期使用方式 |
|---|---|---|
| `S_REQ` | 行列递增值、下一组剩余行数、下一列地址偏移 | 保存当前描述符及合并输出的范围信息 |
| `S_START` | 递增值的范围判断、行列末尾判断 | DMA 启动时保存下一块控制和有效行列数 |
| `S_WRITE` | 下一块控制与递增结果 | DMA 完成时更新当前块索引及输出范围 |

递增结果直接参与块完成时的行列索引选择。下一块行列索引不另设一组寄存器。下一组行数的减法和范围比较、下一列偏移的加法和范围比较也分属不同周期。

公开接口、DMA 请求和启动周期、输出数据握手、完成事件、容量及并行数量保持不变。复位和重新配置优先于正在进行的状态转移。新增的数据寄存器按周期采样，状态机保证其在有效消费之前完成更新。

## 形式证明

`run_formal.py` 读取实际 RTL，并与提交 `8b46373c` 中的完整 `oa_writer` 比较。证明包含所有公开输出、共同状态，以及内部控制实际被消费时的下一块信息。比较公开输出时包括无效数据周期。

证明直接检查实际状态转移产生的关系：

- 请求状态之前存在空闲周期，递增和下一组剩余行数已经对应当前块。
- 启动状态之前存在请求周期，范围与末尾判断已经对应当前块。
- 写入状态之前完成 DMA 启动，下一块控制已经保存。
- 写入期间块索引保持，完成事件使用的递增结果和下一块控制属于同一块。

原设计在请求状态保存的下一块信息，以及当前设计在启动状态保存的下一块信息，分别具有独立断言。所有断言与逐周期输出一致性共同接受时序归纳检查。配置数值与外部握手不施加范围限制。

证明参数为 `VLEN:BUS_WIDTH:COUNT_WIDTH`：`4:32:4`、`8:64:6`、`16:32:7`、`16:64:8`、`16:64:16`、`16:64:29`、`16:64:32`、`32:64:32`。

## 实际模块协议测试

复用 `test/oa_writer/run_equivalence.py`，同时实例化当前设计和参考设计，逐周期比较全部 21 个公开输出。参数为 `4:32:8`、`8:64:8`、`16:32:16`、`16:64:16`、`16:64:28`、`16:64:29`、`16:64:32`、`32:64:32`。每组运行 512 个配置，覆盖尾块、零维度、有限位宽回绕、WS/IS、S8/S16、合并输出、随机等待、复位及配置中断。

八组测试全部通过，共 4096 个配置、4,178,136 个周期、128,375 次 DMA 请求、19,793 次合并组启动、2214 次计算完成和 1429 次配置中断。形式证明、协议测试及资源测量均记录同一份 RTL 的 SHA-256。

## 原生 RTL 测量

生产参数为 16 通道、64 位总线、29 位维度计数器。使用相同的原生 Xilinx 算术映射及 ABC9 参数，六种 LUT 输入宽度的映射成本均为 1。

| 版本 | 逻辑 LUT | FF | DSP | 本次预计算路径 | 完整模块最长路径 |
|---|---:|---:|---:|---:|---:|
| `8b46373c` | 1414 | 780 | 0 | 16 | 16 |
| 当前设计 | 1397 | 851 | 0 | 9 | 12 |

完整模块的 12 级路径位于列地址加法。该测量未进行额外算术单元 DSP 替换、物理 LUT 合并或布局，实际器件频率由完整 Vivado 实现报告给出。

## 运行方法

需要 Python 3、带 `read_slang` 的 Yosys Python 包 `pyosys`、Verilator 和 C++ 编译器。工具应已加入当前环境的 `PATH` 与 Python 模块路径。

```sh
python test/oa_writer_pipeline/run_formal.py --out /tmp/oa_writer_pipeline/formal

python test/oa_writer/run_equivalence.py \
  --reference 8b46373c \
  --profiles 4:32:8 8:64:8 16:32:16 16:64:16 16:64:28 16:64:29 16:64:32 32:64:32 \
  --verilator verilator-modern \
  --out /tmp/oa_writer_pipeline/numeric

python test/oa_writer_pipeline/measure.py --out /tmp/oa_writer_pipeline/mapping
```

各步骤顺序运行。结果包含源码摘要、证明日志、协议计数和组合路径。大型映射网表使用 gzip 保存；仓库中的 `measurement.json` 保存当前设计的通过结果。
