# im2col 范围与状态更新验证

`conv_im2col_frontend.sv` 在 `LANES <= 8` 时，提前计算当前通道的剩余数量，并为每个固定传输步长准备组内范围。范围更新沿用现有配置接收、描述符提交、坐标译码和数据写入周期。

## 范围计算

设组内通道数为 `C`，当前通道为 `a`，本拍传输数量为 `s`。下一通道按十六位计算：

\[
 a'=(a+s)\bmod 2^{16}.
\]

剩余数量及通道资格保持十七位模运算：

\[
 d'=(C-a')\bmod 2^{17},\qquad valid_{\ell}=[\ell<d'].
\]

生产实现先计算 `remaining = C - a`。每个固定步长同时检查十六位通道回绕，并比较剩余数量的低位是否处于 `[s, s+lane]` 区间。该区间覆盖全部可能产生无效输出通道的较小剩余值。高位关系与回绕关系独立计算，当前传输数量只选择已经准备好的范围。

组末条件从已保存的 `group_range_q` 相邻位获取。每种固定步长预先选择组首范围或递增后的范围，再根据传输数量合并结果。

## 保存事件与行末条件

范围候选使用当前组范围、有效列数、行内列数、字内范围和输出宽度生成传输资格。在八路及更小输出配置下，每次输出传输同时准备后续范围。补零期间保存的组范围由有效列资格屏蔽，重新进入有效数据前由行首、描述符或译码事件装入。

行末计算分别生成数据区与补零区的通道条件。对每种输入格式，整体行末条件为：

\[
 end = end_{data}\lor(past\_active\land end_{padding}).
\]

这一表达式保持原有逐通道逻辑的四态传播，同时将 `past_active_q` 的作用集中到最终条件合并。

通用分支的流式保存资格分别计算运行状态与行列位置。八路及更小输出配置将保存资格与范围数据选择分开，配置接收、描述符提交、坐标译码和流式输出保持既有优先次序。

## 状态选择与数据保存

流式传输先计算行切换、组切换、补零和数据字边界对应的目标状态。缓存就绪只控制最终的请求状态选择，`word_output_q` 与状态寄存器同时保存。

字内范围分别计算各地址来源的可用字节，公共写入资格控制保存边沿，数据由互斥的地址更新来源选择。状态有效位使用异步复位；窗口、配置乘积、预取与译码运算的数据寄存器在时钟边沿保存，写入条件由相应有效状态保护。

## 执行验证

在仓库根目录执行：

```bash
python3 test/frontend_group_feedback/check.py \
  --out build/frontend_group_feedback/formal_clean

python3 test/frontend_group_feedback/stream_control.py \
  --out build/frontend_group_feedback/stream_control_clean

python3 test/frontend_pipeline/check_control.py
```

`check.py` 从生产 RTL 提取计算表达式，完成以下检查：

| 检查项目 | 范围 |
| --- | --- |
| 组内范围模运算 | `LANES=1..8`，全部十六位组通道数与当前通道编码，传输数量为 `0..LANES` |
| 组末选择 | 任意已保存范围与组首范围，逐一检查全部固定步长 |
| 有效列内的传输资格 | 连续范围选择与最高有效通道选择；覆盖四字节和八字节的窄输出限制 |
| 行末布尔关系 | `LANES=1..8`，全部输入条件和两种输入格式 |
| 行末四态传播 | `LANES=1/2/4/8`，共 400,000 次随机 `0/1/X/Z` 比较 |

形式检查共 44 项。范围算术检查同时覆盖十六位通道递增回绕、十七位减法回绕、组长度为零和零步长。

`stream_control.py` 从实际 RTL 提取状态选择、字内范围和通用分支的范围保存资格，执行 14 项形式检查，覆盖行地址寄存开关、四种缓存字宽度与八种范围参数组合。短范围分支的补零状态与恢复关系由 `test/frontend_pipeline/check_control.py` 检查。

完整前端的事务序列、配置准备和数值检查见 [运算分级与资源共享验证](../frontend_pipeline/README.md)。测试使用实际前端、缓存和 AXI 读取模块，持续提供描述符，并检查写入数据、位置、掩码、完成、错误和随机背压下的数据保持。当前源码及形式检查结果保存于 `validation.json`。
