# 缓存存储与范围判断验证

`conv_windowed_cache` 使用公共 `regfile` 保存每一路的有效位。需求查询、预取查询、两个预取候选、替换选择和提示更新分别读取对应地址。配置过程逐行清除有效位；填充过程中，该存储行的有效状态由填充寄存器屏蔽；填充结束后写入成功或失败状态。前一行完成与下一行开始可以在同一周期发生。

请求接收时计算地址范围，将结果作为描述的一部分保存到需求队列。`work_request` 和活动缺失请求继续携带该状态，出队选择只处理已经保存的判断结果。配置只有在既有事务全部完成后才能改变。

八项预取描述保存在公共 `regfile` 中，每项包含64位地址/代次信息和65位索引/替换信息。逻辑队列位置通过三位映射选择物理存储位置。移除非队首项时交换其位置映射与队首映射，描述数据只在入队时写入。逻辑有效位和物理有效位分别记录顺序和存储占用，保留当前代次优先的选择次序。

## 功能比较

```sh
python3 test/cache_pipeline/run.py --jobs 2
python3 test/cache_storage/compare.py
```

`compare.py` 从指定 Git 提交生成独立参考模块，并让当前模块和参考模块接收完全相同的请求、配置与 AXI 返回。默认参考提交为 `aa2ef9a3`，可通过 `--reference-commit` 指定其他提交。测试覆盖32位和64位总线、两种缓存路数、请求深度1和4，共六组配置。全部控制输出逐周期比较，响应数据和 AXI 地址在各自有效时比较。

每组配置执行十三种场景：排队读取、连续命中、响应背压、缓存行竞争、地址范围错误、填充错误及恢复、预取等待、预取错误及恢复、配置等待、复位、部分字节旁路、几何提示顺序和预取队列压力访问。

压力场景检查八项全部占用、不同代次的非队首移除、循环使用存储位置，以及同一周期入队和移除。活动预取的地址、索引、代次、替换信息和所有队列状态也与参考模块逐周期比较。仿真断言检查位置映射始终构成完整排列，以及逻辑占用、物理占用和队列计数一致。

## 资源测量

```sh
python3 test/cache_storage/synthesis.py --out build/cache_storage/synthesis
```

测量参数固定为128组、两路、16字节缓存行、64位总线和四个在途请求。脚本保存输入源码副本，并记录源文件摘要、逻辑LUT、触发器、存储原语以及最长组合逻辑节点序列。该节点数量用于检查逻辑结构；150 MHz需要结合目标器件的实际时序结果检查。

替换来源的写入选择与资源测量见 [RANK_SOURCE.md](RANK_SOURCE.md)。

预取标签的同步读取端口共享见 [TAG_READ_PORTS.md](TAG_READ_PORTS.md)。
