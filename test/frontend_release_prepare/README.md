# 缓存行释放计算的配置准备

`conv_im2col_frontend` 在已有的两拍配置准备阶段保存行偏移和限幅阈值，使请求阶段的加法与范围判断可以并行执行。请求接收、预取采样和配置完成仍使用原有状态与时钟边沿。

设输入行号为 `Y`，上方补边为 `P`，右移位数为 `s`，最后一个输出行号为 `L`，短像素标记为 `e`。原行释放结果为：

```text
x = (Y + P) >> s
result = x < L ? x + e : L
```

配置阶段准备 `B = P + e * 2^s` 和有符号阈值 `T = L * 2^s - P`。运行阶段并行计算 `(Y + B) >> s` 与 `Y >= T`，再选择限幅结果。`T` 的负值和超过 16 位行号范围两种情况各用一位保存。高、低九位分别计算加法结果，高九位同时准备两种进位结果。

预取输入选择在原 `prefetch_phase` 状态转换时保存。准备阶段复用最终阈值寄存器，第一拍保存移位后的低位及范围分类，第二拍完成补边减法。全部运算保留完整输入范围，包括零输出高度对应的模减法结果。

## 形式检查

```bash
python test/frontend_release_prepare/run_formal.py --out build/frontend_release_formal
```

默认参考提交为 `2297cb12deac56b476f9a2a656da4038a9d8a75c`，可通过 `--reference-ref` 指定。脚本先确认前端其他源码保持一致，再执行 22 项证明：

- 两个计算端口的 164 位自由输入、64 位输出等价，以及九位分组加法的 33 位自由输入、18 位输出等价。
- 在通用和实际 FPGA 分支中，分别使用三组前端参数证明配置系数、预取选择和请求接收条件，共 12 项状态归纳。
- 在两种分支中，分别使用深度 1、2、4、8 的缓存请求队列证明有效工作项只使用有效输入元数据，共 8 项状态归纳。

状态证明直接展开当前 RTL，保留实际配置捕获、准备状态、请求计数和队列指针更新。子模块输出及与所证明控制无关的算术结果作为自由输入，不增加外部输入约束。证明覆盖复位后的任意输入序列。

缓存检查为每一份描述记录有效输入标记，并从实际 `lookup_read_request` 选择代码生成相同的标记选择。队列位置关系、有效项标记以及工作项标记一起通过无界归纳。行释放元数据在需求出队和命中元数据更新时消费，这两个事件都要求有效工作项。配置准备阶段不存在需求请求或预取结果采样，因此准备期间的内部系数不会进入有效事务。

## 协议与数值检查

```bash
python test/frontend_release_prepare/run_protocol.py \
  --out build/frontend_release_protocol --verilator verilator-modern
```

该入口复用 `test/window_dma` 的真实 DMA、前端、缓存和 FPGA 存储模型。两次编译共用全部依赖，只有前端文件取指定参考版本。完整窗口回归包含并发普通读取、背压、读取错误、配置等待、预取期间配置、请求取消及复位恢复。

新增 48 组输出高度、步长、补边和通道数组合，覆盖短像素和普通像素、最后一个输出位置、归约尾部和随机请求。结果如下：

| 检查项目 | 结果 |
|---|---:|
| 原有窗口协议场景 | 15 项通过 |
| 原有接收请求 / 有效元素 / 错误响应 | 422 / 4,457 / 19 |
| 新增参数组合 | 48 |
| 新增接收及完成请求 | 1,152 |
| 新增数值比较 | 9,571 |
| 新增逐周期记录 | 64,361，全部相同 |

脚本默认清理可重建的 C++ 编译中间文件，并压缩周期记录。`--keep-objects` 保留模型对象，以供后续数值场景复用。

## 普通 RTL 映射

```bash
python test/frontend_release_prepare/measure.py \
  --out build/frontend_release_measurement --frontend
```

完整前端使用 `SIZE=16`、`LANES=4`、128 个集合、2 路、16 字节缓存行以及 `CACHE_POLICY=3`。生产实例的前端内部 AXI 宽度为 32 位。`--frontend-width 64` 可测量另一组合法参数。前后版本共用所有依赖和综合选项，算术由普通 RTL 推断。

| 测量范围 | 修改前 LUT | 修改后 LUT | 修改前 FF | 修改后 FF | 完整范围最长组合级数 |
|---|---:|---:|---:|---:|---:|
| 两个行释放计算端口及配置准备 | 219 | 313 | 142 | 180 | 15 → 9 |
| 完整前端，内部总线 32 位 | 12,422 | 12,528 | 6,012 | 6,044 | 15 → 15 |
| 完整前端，内部总线 64 位 | 12,448 | 12,514 | 6,011 | 6,043 | 16 → 15 |

32 位完整前端中，坐标寄存器到缓存行释放字段的最长路径从 14 级缩短到 12 级；64 位参数中为 14 级到 13 级。两种完整前端的 DSP 数均保持 43；RAMB18 数分别保持 23 和 25。独立计算块的结果用于分析其算术结构，完整前端和整机分别检查跨模块路径。

`measurement.json` 保存源码摘要、证明结果、协议统计、资源和完整路径分析摘要。器件频率及实际 Slice LUT 使用量由后续 Vivado 综合与实现报告确认。
