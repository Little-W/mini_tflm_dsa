# 窗口队列的准备位置与多在途请求

`conv_window_queue` 按接收顺序保存描述符和标签，已经发送给前端的请求计入 `active_count`，标签一直保留到对应的外部末拍被接收。`p_frontend_outstanding` 指定前端允许同时保存的请求数量。

待发送位置 `present` 使用独立寄存器保存。启动一个描述符时，该位置前移；错误排空过程中，如果当前已经没有在途项，接收错误末拍也使待发送位置前移。请求总数、在途数、接收位置和完成位置分别保存并保持一致。

未发送数量的非空标志和大于一项的标志并行计算。启动事件只选择是否消耗唯一的准备项。同周期新接收且没有未发送项时，输入描述符直接保存到转发寄存器。该处理支持空闲接收、末拍同时启动后续请求及连续单拍窗口。

| 接收与返回数量 | 合计 36,096 个请求，返回顺序、标签、列位置、掩码、数据和末拍均检查 |
| 持续接收 | 连续单拍窗口保持每周期一次启动，达到各配置的在途容量 |
| 背压与恢复 | 每组包含随机请求、返回延迟和消费停顿，共 64 次错误排空和重新配置 |
| 列范围 | 检查零列、有效列及超出最大列数的描述符资格 |

形式检查要求第一个采样边沿复位，后续输入均可任意变化。该检查针对队列状态不变量和转发关系；数据次序及数值由独立事务模型逐次核对。
