# 量化输入寄存阶段验证

本测试验证最终计算输出的数据、有效位与 tile 结束标志共同增加一个寄存边沿后，现有 `vec_requant` 能否正确接收整组数据。`requant_group_buffer` 继续保存 512 行，每行包含 16 个 INT32 和一个 tile 结束位，生产容量保持为 `512×513=262,656` 位。

## 容量预留

形式模型在实际 `requant_group_buffer` 前放置一个生产者寄存阶段，保留完整的组开始、清空、输入、读取和输出事件。检查以下关系：

```text
未完成预留 = 尚未产生的行 + 生产者寄存器中的行 + RAM中的行 + 已读出的行 + 已发射且尚未输出的行
```

深度 **1、3、16、512、1,024** 全部通过归纳证明。输入间隔、读取背压、输出等待、复位与清空可任意变化。输入条件仅要求组开始时具备容量、生产者行数不超过本组预留，以及输出只释放已经发射的行。

证明同时检查每个计数器与地址的范围，以及 `o_group_ready` 为真时生产者寄存器、RAM、读出阶段和量化流水均无未完成行。原有整组预留因此覆盖增加的一个输入寄存边沿。

## 数值与参数等待

仿真实例化两个完整的 `vec_requant`，均使用两个计算通道与 512 行缓存。第一个实例直接接收输入，第二个实例的数据与标志共同延后一拍。两个实例分别与已有的 128 位整数参考计算比较，并逐行检查 INT8、INT16 和 tile 标志。

组开始不等待参数 DMA 完成，整组可以先进入输入缓存。DMA 授予与返回间隔独立变化。取消操作可紧接生产者输入边沿发生，覆盖仍有有效行停留在新增寄存器中的情况。

本次 `BUS_WIDTH=64`、`VLEN=16`、`p_compute_lanes=2`、512 行配置使用官方 Xilinx 原语功能模型，启用 Verilator 断言与 UBSan，结果如下。

| 项目 | 结果 |
|---|---:|
| 场景数 | 96 |
| 组数 | 180 |
| 完整 512 行组数 | 15 |
| 仿真周期 | 87,139 |
| 两个实例合计输出行数 | 19,617 |
| INT8/INT16 元素比较次数 | 627,744 |
| 输入与参数等待重叠周期 | 1,905 |
| 配置清空次数 | 7 |
| 复位恢复次数 | 6 |
| 参数 DMA 命令数 | 578 |

覆盖内容包括 WS/IS、逐张量/逐通道量化、S8/S16、尾行尾列、完整组预留、输入间隔、参数等待、复位和清空。两个实例的输出时刻按各自输入到达与参数等待计算，数值和有效输出行序分别对照参考结果。

本目录验证量化接收与预留机制；实际计算核心的输出寄存、偏置组切换和完整 NPU 调度由计算核心及整机测试检查。

## 运行

使用包含 `pyosys`、`read_slang` 和 Xilinx 单元库的 Python 环境，并将支持当前 SystemVerilog 源码的 Verilator 加入 `PATH`。

```bash
python test/requant_input_stage/run.py \
  --out /tmp/requant_input_stage --verilator verilator-modern --xilinx
```

`--formal-only` 与 `--simulation-only` 可分别执行形式检查和数值仿真。输出目录保存脚本、直接编译的测试源码、日志、可执行程序和源码 SHA256；可重建的编译中间文件在通过后清理。`measurement.json` 保存本次结果。
