# 四通道算术分组的完整映射验证

## 验证流程

`run.py` 调用实际 `select_cells(..., pack_small_alu=True)` 和
`apply_mapping`。原设计和改写后的设计分别保存为 JSON，由 Yosys
真实导入，完成单通道或四通道 DSP 技术映射，再比较全部公开输出。

原算术保留 `$alu`，使用 Yosys 内建 SAT 模型；映射后的 `DSP48E1`
使用官方功能模型。每个算术单元的全部 `X`、`Y` 和 `CO` 都连接至
比较输出。输入操作数、每通道 `CI` 及共用的变量 `BI` 不施加数值限制。
零位操作数按常量零扩展，并由具有空输入连接的原始 `$alu` 直接参与比较。

脚本同时检查：

- 实际 DSP 数量等于选择报告，计入预留后的数量满足预算。
- 公开端口与原 JSON 保持相同，全部自定义技术映射单元完成替换。
- 原设计、映射设计与比较设计均通过 `check -assert` 连接检查。
- 每个补位采用独立连接编号，原输出连接保持不变。
- 具有组合依赖的两个运算不会同时选入独立 DSP 集合。

## 覆盖范围

| 测试类别 | 检查内容 | 结果 |
| --- | --- | --- |
| 基本连接 | 1 至 10 位结果、组内有符号与无符号混合、扩展、截断、独立 CI、变量 BI | 通过 |
| 零位操作数 | A 空输入、B 空输入、双方空输入、有符号与无符号扩展 | 通过 |
| 部分通道 | 两路、三路、四路，以及单独一条运算 | 通过 |
| 预算 | 零预算、仅容纳一组、预留 DSP、宽算术与窄算术共存 | 通过 |
| 信号关系 | 不同 BI、常量 BI、常量和重复输入、组合依赖 | 通过 |
| SoC 实际参数 | 76 个分组、303 个窄算术单元对应的全部 57 种有序参数组合 | 通过 |

共完成 75 项端到端 SAT，其中 18 项覆盖连接、选择及预算行为，57 项
覆盖实际 SoC 分组参数。实际参数比较允许输入和 `BI` 自由变化，因此
同时覆盖各组的常量输入配置。

`measurement.json` 保存 mapper、技术映射 RTL、官方模型及网表的摘要，
以及每项比较的参数、DSP 数量、完整输出位数和结果。

## 运行方法

基础场景：

```sh
python3 test/fpga_alu4_mapping/run.py --out build/fpga_alu4_mapping
```

同时验证实际选择报告中的全部分组参数：

```sh
python3 test/fpga_alu4_mapping/run.py --out build/fpga_alu4_mapping_soc \
  --selection build/soc/pre/soc_top/wide_alu_mapping.json \
  --selected-netlist build/soc/pre/soc_top/pre_alu.json
```

`--mapper` 可以指定待验证脚本。执行时将该脚本及依赖复制到输出目录，
使全部比较使用同一版本。实际选择报告必须与指定输入网表的 SHA256
相同；同一参数组合的各个 SoC 分组共享一次全输入证明。
