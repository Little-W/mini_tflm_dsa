# Softmax 分段归一化与倒数更新验证

## RTL 结构

`vector_softmax` 将有效累计值的归一化分为两个周期。`NORMALIZE` 检查累计值范围，并保存八位粗移位结果；`NORMALIZE_COMMIT` 完成四位、两位和一位细移位，生成倒数计算所需的分母与输出移位量。有效累计值为 `[2^19, 2^31)`，全部有效输入保留原有整数精度。

倒数舍入按四个字节并行递增，各字节进位由低位全一条件产生。正向饱和条件直接从舍入前的商计算。倒数初值和迭代更新共用一组加法器，高半字提前计算两种进位结果，再由低半字进位选择。

有效任务增加一个内部周期。输入、指数缓存和输出缓存的容量保持不变；查表请求、响应、输出次序和错误返回方式保持不变。归一化增加 33 位寄存状态，复位后由状态机保证这些数据只在有效采样后使用。

## 验证范围

脚本直接提取当前 RTL 中的表达式，与提交 `9a6437f4` 的对应表达式进行形式比较：

| 项目 | 自由输入 | 检查内容 |
|---|---:|---|
| 归一化 | 32 位累计值、使能与复位 | 全部已定义累计值的范围检查、有效分母与移位量、采样及保持 |
| 倒数舍入 | 33 位有符号商、1 位递增条件 | 全部已定义输入的 32 位结果 |
| 共享估计加法 | 32 位估计、32 位倒数、1 位状态选择 | 初值与更新结果，包括原有饱和处理 |

## 本地资源与组合深度

对完整 Softmax 模块使用相同的原生 Xilinx 算术映射和 ABC9 参数，最大深度设为 16，乘法延迟设为 2。六种 LUT 输入宽度的映射成本均为 1。

| 版本 | 逻辑 LUT | FF | DSP | 最长寄存器路径 | 归一化路径 |
|---|---:|---:|---:|---:|---:|
| `9a6437f4` | 505 | 249 | 1 | 13 | 13 |
| 当前设计 | 504 | 282 | 1 | 9 | 5 |

这里统计映射后的逻辑单元和组合级数，未进行额外算术单元 DSP 替换、物理 LUT 合并或器件布局。实际 Vivado 时序应由包含本模块的完整实现报告给出。

## 运行

需要 Python 3、带 `read_slang` 的 Yosys Python 包 `pyosys`、Verilator、C++ 编译器，以及仓库中的 TFLM 源码和 gemmlowp 依赖。工具应已加入当前环境的 `PATH` 与 Python 模块路径。

```sh
python test/vector_softmax_normalize/run.py \
  --out /tmp/vector_softmax_normalize \
  --tflm-root drivers/tflm/tflm/tflite-micro \
  --verilator verilator-modern
```

输出包含形式证明日志、完整模块映射结果、四组仿真程序、源码摘要和 `summary.json`。脚本顺序编译，完成后删除可重新生成的编译目录；大型网表采用 gzip 保存。仓库内的 `measurement.json` 保存当前设计的通过结果和源码摘要。
