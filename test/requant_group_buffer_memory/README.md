# 量化整行缓冲的 SRAM 功能验证

`requant_group_buffer` 在 `ASIC_SRAM` 配置下使用 `smic40_sram_1r1w`，每行包含全部 INT32 数据和 `tile_done`。行为级实现使用同步读 `regfile`。两种实现共用行地址、读写使能和预留控制。

## 存储配置

生产 NPU 使用 16×16 阵列和七个 8 KiB 共享 bank。关闭 IA 紧凑存储时，最大 IA 复用数量为 16，量化缓冲为 256 行；开启时最大复用数量为 32，缓冲为 512 行。

| 项目 | 256 行配置 | 512 行配置 |
| --- | ---: | ---: |
| 每行 INT32 数据数量 | 16 | 16 |
| 每行逻辑位数 | 513 | 513 |
| 逻辑存储容量 | 131,328 位 | 262,656 位 |
| SRAM 宏 | 66 个 `RAMTP128X16` | 33 个 `RAMTP1024X16` |
| 深度方向宏组数 | 2 | 1 |
| 每组并排宏数量 | 33 | 33 |
| 物理存储容量 | 16.5 KiB | 66 KiB |
| 容量利用率 | 97.159% | 48.580% |

封装对不超过 384 行的存储采用 128 行宏组合，更深的存储采用 1024 行宏。该选择综合考虑宏面积和存储形状。宏面积统计与完整 ASIC 综合面积分别记录。

读使能有效的时钟沿更新输出，未使能时保持输出。清空和复位重置队列控制，存储内容和读出数据保持原有行为。

## 逐周期数据验证

```sh
python3 test/requant_group_buffer_memory/run.py \
  --out build/requant_asic_memory --verilator verilator --jobs 2
```

测试实例化生产 SRAM 封装和保存全部存储位的同步功能模型。参考实例使用同一控制 RTL 的行为级 `regfile`，独立队列逐位记录输入行。功能模型在宏发生同地址并发读写时终止仿真。

测试深度为 1、3、16、127、128、129、256、384、385、511、512、513、1024。256 和 512 行配置使用完整的 16 路 INT32 数据，其余配置使用一路 INT32 数据。两轮满容量写入分别将每个逻辑存储位设置为零和一，随后检查随机数据、部分组、地址回绕、跨宏边界、输入间隔、输出背压、清空和复位。

本次 13 种深度共比较 39,642 行输出、5,188,506 个已消费数据位。256 行配置检查 2,635 行输出，512 行配置检查 5,449 行输出。全部检查通过。

## 控制与地址证明

```sh
python3 test/requant_group_buffer_memory/run_control.py \
  --out build/requant_asic_control
```

归纳证明检查整组预留覆盖全部未完成行、读写地址范围、循环地址距离，以及同时读写时地址不同。输入条件为整组仅在 `ready` 有效时预留，行数不超过容量，输入不超过已预留行数，输出只消费已发射行。组到达时间、输入间隔、背压、流水完成时间、复位和清空可以任意变化。

运行脚本保存源文件 SHA-256、工具版本、命令和逐配置结果。`measurement.json` 收录功能与控制检查结果；完整 NPU 的存储数量由 `test/requant_group_buffer_npu` 检查。
