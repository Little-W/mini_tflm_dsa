# 量化整行缓冲的 SRAM 功能验证

`requant_group_buffer` 在 `ASIC_SRAM` 配置下使用 `smic40_sram_1r1w`，每行包含全部 INT32 数据和 `tile_done`。通用配置使用同步读 `regfile`。两个分支共用行地址、读写使能和预留控制。

默认配置如下。

| 项目 | 数值 |
| --- | ---: |
| 每行 INT32 数据数量 | 16 |
| 每行逻辑位数 | 513 |
| 逻辑行数 | 512 |
| 逻辑存储容量 | 262,656 位 |
| 每个宏的行数和位宽 | 128 × 16 |
| 深度方向的宏组数 | 4 |
| 每组并排宏数量 | 33 |
| `RAMTP128X16` 总数量 | 132 |
| 物理存储容量 | 270,336 位，33 KiB |
| 字宽填充位 | 7,680 位 |

宏的深度固定为 128，完成标志与该行数据使用相同的地址。读使能有效的时钟沿更新输出，读使能无效时保持输出。清空和复位重置队列控制，存储内容和读出数据保持原有行为。

## 逐周期数据验证

```sh
python test/requant_group_buffer_memory/run.py \
  --out /tmp/requant_asic_memory --verilator verilator-modern --jobs 2
```

测试实际实例化生产 SRAM 封装和保存全部宏存储位的同步功能模型。参考实例使用同一份控制 RTL 的通用 `regfile` 分支，另有独立队列逐位记录输入行。功能模型遇到同地址并发读写会终止仿真。

测试深度为 1、3、16、127、128、129、511、512、513、1024。其中 512 行配置使用完整的 16 路 INT32 数据，其余配置使用 1 路 INT32 数据。两轮满容量写入分别将每一个逻辑存储位设置为零和一，随后进行随机数据、部分组、地址回绕、跨宏边界、输入间隔、输出背压、清空和复位检查。

已完成的测试共比较 33,045 行输出、3,941,205 个已消费数据位。默认配置比较 5,939 行输出，覆盖 2,199 次并发读写和 6,491 次输出保持检查。全部检查通过。

本测试使用同步 SRAM 功能模型，记录数据和掩码行为；工艺库模型与静态时序需在具备对应工具和库文件的环境中运行。

## 控制与地址证明

```sh
python test/requant_group_buffer_memory/run_control.py \
  --out /tmp/requant_asic_control
```

10 种深度均通过 SAT 归纳证明，检查以下性质：

- 整组预留覆盖尚未到达、存储中、读出中和算术流水中的全部结果行。
- 读写地址始终位于有效行范围，循环地址距离与尚未读取的行数一致。
- 同时进行读写时，读地址与写地址始终不同。

证明沿用模块的输入协议：整组仅在 `ready` 有效时预留，行数为 1 至容量；输入行数不超过已预留数量；输出只消费已发射的行。组到达时间、输入间隔、背压、流水完成时间、复位和清空均可任意变化。

运行脚本生成源码 SHA-256、工具版本、命令和逐配置结果。随仓库保存的结果摘要见 `measurement.json`。
