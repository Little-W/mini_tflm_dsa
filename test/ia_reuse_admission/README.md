# IA 加载边界与请求许可

加载控制器分别比较普通组、尾组和预取组的上界，再选择当前组的结果。配置值先转换为 `count_t`，再转换为 `LOAD_CNT_W`，保留截断和扩展顺序。预取上界按 `LOAD_CNT_W` 位解释。

加载游标与下一位置在同一边沿更新。复位、组切换和预取进入分别保存零与一；分块完成时共同前进。边界比较覆盖定宽回绕。普通行与尾行的行数比较各自完成，状态选择比较结果。

剩余请求条件同时检查当前游标小于组上界，以及已完成数量不等于组上界。三种上界并行完成比较；槽号对应的忙碌位、有效位及加载状态共同决定是否可以启动下一次加载。

`ia_loader` 将缓存资格、模式条件及查询就绪分别计算，再产生请求与授予。`p_register_dma_request=1` 时，请求在时钟边沿保存，配置切换和缓存清除撤销尚未提交的请求；授予同时要求已保存的请求有效。直接接口使用当周期请求条件。

## 验证

`run_control.py` 直接提取当前 RTL，检查游标保存关系、边界与行数选择、剩余请求条件，以及直接和寄存请求接口。输入覆盖查询就绪、缓存资格、预取、忙碌、初始化、清除和授予的全部二态组合。

游标关系使用复位初始检查及一步无界归纳；寄存请求同样证明复位后的任意后续输入及一步状态归纳。加载计数覆盖 1、2、3、4、7、8、12 位，包含计数配置窄于加载游标的情况。ASIC 和 FPGA 编译配置均参与检查。

```bash
python3 test/ia_reuse_admission/run_control.py \
  --current-root . --out build/ia_reuse_control
```

每项检查保存所用源文件、实际提取模型及日志的 SHA-256。完整模块的输入数据、预取和状态比较参见 [IA 请求捕获验证](../ia_lookup_capture/README.md) 与 [槽号和行数验证](../ia_slot_stage/README.md)。
